# 信息密度与层级规范

> 目标：每个组件在每种尺寸下都做到 **glanceable（一眼看懂）**，而不是把功能平铺出来。
> 这份文档是 task-9 的验收依据；每个组件改完要对照"信息预算"逐条打勾，并交 before/after 截图。

## 1. 三条硬规则

1. **每个尺寸有信息预算**（见下表），超预算必须降级到二级区域或详情/菜单。
2. **每张卡片只有一个 Primary**：一个最大值/主状态；一个 Primary Action（可选）。
3. **Chrome on demand**：设置齿轮、标题栏、删除/改尺寸等操作，**默认不显示**，只在长按进入编辑模式或悬停时出现。
4. **静态 identity 行**（v0.4.0，D-33）：每张卡内容区第一行允许一条 24px identity 行（24×24 identity chip + 12px 组件名 +
   可选 trailing 辅助信息）。它**不是 chrome**——没有可交互控件、不常驻操作、不占点击热区；**不计入下面的信息预算**，
   其余门禁（最小字号、主次比、空带、内容带、横向空洞）不变。

## 2. 尺寸信息预算

| 尺寸 | 允许的 Primary | 允许的 Secondary | 允许的 Tertiary | 主操作 |
|---|---|---|---|---|
| `1×1` | 1 个数值/状态 | 1 个标签（≤6 字） | 0 | 0 |
| `2×1` | 1 个数值/状态 | 1–2 个辅助值 | 0 | 0（点击即主操作） |
| `1×2` | 1 个数值/状态 | 2–3 行列表/辅助 | 0 | 0 |
| `2×2` | 1 个数值/状态 | 2–4 项 | 0 | ≤1 |
| `3×2` | 1 个数值/状态 | 4–6 项 | 0 | ≤1 |
| `3×3` | 1 个主区域 | 列表/图表 | 1 个入口（菜单/详情） | ≤1 |
| `4×2` | 1 个主区域 | 分栏辅助 | 1 个入口 | ≤1 |

> **内容列表例外**：组件声明的内容列表（todo 任务行、weather 逐时/7 天、日历格）按「行/列」计为 1 个 Secondary 区块，不逐项累加；行数上限见 D-04：todo 2×2≤4、3×2≤6、3×3≤10；weather 2×2 逐时≤6 列、3×2 逐时≤6 列。weather 3×2 的「今日指标」（体感 / 降水概率 / 风）整组按 **1 个 Secondary 区块**计（不按 3 项累加）。

### 2.1 量化门禁（v2，2026-10-19，来自第二版独立审计）

> 判定的物理前提：2880×1920 物理屏 = 1440×960 CSS @200% = 267 PPI，**1 CSS px = 0.1902 mm**；
> 距离 D(mm) 处 1 CSS px ≈ `653.9 / D` 弧分；20/20 视力下"舒适可读"取 ≥10′ 帽高（≈0.7em）。
> 主信息按 **1.0–1.5m 远看**，次要按 0.5–0.8m，次次要/标签 ≤0.5m。

| 角色 | 绝对下限 | 推荐 | 说明 |
|---|---|---|---|
| 主信息（数字/时间/状态） | **32px** | 40–96px（按尺寸档） | 32px 在 1.5m 帽高 9.8′≈2× 极限；40px=12.2′ |
| 单值卡 hero（1×1 / 2×1） | **40px** | **48–68px** | 1×1 时钟/计时/久坐/计数至少 48px |
| 次要值（温度、日期、统计值、任务标题） | **14px** | 16–20px | 14px 在 0.6m 帽高 10.7′ |
| 标签（单位、星期、计数标签） | **12px** | 14px | 12px 只在 0.5m 可读 |
| 元信息（时间、逾期、行尾辅助） | **12px** | 12–14px | **10px 禁止**（任何距离都 <10′） |

**可测指标（每插件 × 每尺寸都要满足）**

1. **主信息占比** `主信息字号 / iframe 高度`：1×1 ≥30%、2×1 ≥30%、2×2 数值卡 ≥12.5%、3×2 数值卡 ≥15%、4×2 数值卡 ≥17%；列表卡用"列表头主层"替代（计数/标题 ≥28px）。
2. **主次字号比** ≥2.0（数值卡）或 ≥1.5（列表头 vs 组头/行标题）。
   > **列表卡口径（2026-10-20，E7 统一）**：有可量化主信息的列表卡（countdown 事件总数）用 ≥28px
   > 列表头主层；纯列表卡（todo）按 `docs/components/todo.md` 定稿：头部「今日 · N」12 fg3 分组标签 +
   > 行标题 16 承担主信息，**不套用「列表头主层 ≥28」**；其行标题/元信息比按 16/12 记，
   > `verify-widgets` 对 todo 改用行预算、行高 ≥44、行标题 16px、头部文案存在等结构断言。
3. **最小字号** ≥12px；`<12px` 文本数必须为 0。
4. **尺寸递增**：同一插件相邻尺寸档的独立信息项数必须 +1 或更多；持平视为"只缩放不重排"，不合格。
5. **3×2 不得更空**：同插件 3×2 的内容覆盖率（文本+图标包围盒并集高度 / 卡高）必须 > 1×1。
6. **空带**：任意单块空白带 ≤22% 卡高；多块卡片内容带 ≥60% 卡高。
7. **行预算**：列表行高 ≥44px（同时满足触控 40）、行间距 4；行数 = `min(D-04 cap, floor((可用高度 + 4) / 48))`，放不下的必须有滚动/渐隐提示，禁止静默裁切。
8. **字号只走字阶**：Fluent `Text size` 或 `fontSizeBase*`/`fontSizeHero*`（Base100–600 + Hero700–1000）；数字型主信息可按 D-07 使用项目 `Display XL`（48/80/96/112），**文本/标签禁止用 XL**；禁止 `lineHeight: 1`。
9. **横向空洞（v0.3.0，2026-10-20）**：卡片内同一视觉行里，相邻内容单元（flex row 子项 / grid 行内列单元，**不含无内容的布局占位**）之间的连续水平空白 ≤ **40px**。
   - **分栏口径**：同一条带（`data-content-band`）内横向并排的直接子分栏之间，连续水平空白 ≤ **40px**；不得用 `space-between` 把两组推到两端而留出大块中间空洞（grid gap / 组间距本身也须 ≤40）。
   - **定义列表例外**：label 左 / value 右对齐的定义列表行（如 weather 3×2 今日指标）按值列对齐处理，行内留白不算空洞；但该结构必须整块占满剩余宽度、右缘与卡片内容右缘对齐。
   - `scripts/verify-widgets.mjs` 同时测两种口径：内容单元相邻间距（`horizontalMaxGap`）与条带内分栏间距（`bandHorizontalMaxGap`），weather 3×2 均断言 ≤40px。旧 3×2 逐时行里 flex spacer 造成的 166px 行内空白即反例。
10. **3×2 内容带（v0.3.0，weather 三带式）**：整卡内容带 ≥ **70%** 卡高（高于通用 60%）；同时「分栏口径」：
    任一内容分区（`data-content-band` 的直接子分栏）在其 band 内的最大连续垂直空白 ≤ **22%** 卡高（含 lead/trail/internal）。
11. **Secondary 区块结构（v0.3.0，weather）**：3×2 的 Secondary 区块数必须比 2×2 多 1
    （`data-secondary-block` 计数；3×2 = 今日指标组 + 逐时 2 个，2×2 = 逐时 1 个），保证「尺寸变大 → 信息量变多」有可测结构依据。

**间距（全部 spacing token，按尺寸档固定映射）**

| 尺寸 | 卡片 padding | 组间距 | 列表行间距 |
|---|---|---|---|
| 1×1 | 8 | 4 | — |
| 2×1 | 8 纵 / 12 横 | 4 | 4 |
| 2×2 | 12 | 8 | 4 |
| 3×2 | 12 纵 / 16 横 | **16**（v0.3.0 三带式的上带 / 下带内容之间） | 4 |
| 4×2 | 12 纵 / 16 横 | 8 | 4 |
| 3×3 | 16 | 8 | 4 |

- 不允许用 0 或 2px 作为内容行距；不允许各尺寸档共用同一个 padding（如 todo 全档 8px 不合格）。
- 图标与文字：20–24px 图标用 8；≥32px 图标用 12。

**层级表达手段（只用 Fluent token）**

- 字号：Primary 用 Fluent `Text size` / `Hero*`（大卡数字可用 D-07 的 `Display XL`），Secondary 用 `Base300/400`，Tertiary/微标签用 `Base200`；严格遵守 §2.1 的最小字号与主次比，不靠加粗堆层级。
- 颜色：Primary `colorNeutralForeground1`，Secondary `colorNeutralForeground2`，Tertiary `colorNeutralForeground3`；组件 identity 色只出现在 identity chip（D-32），不参与层级。
- 分组：用 `spacingVertical*` 留白分组，**不靠边框/分割线**（Fluent 2 的 card 内部默认无分割线）。
- 操作：次要操作收进 `Menu`，图标按钮必须有 `Tooltip`。

## 3. 渐进披露

- 卡片默认只显示 Primary + 必要 Secondary。
- 详情统一进 `OverlayDrawer`/`Dialog`（Fluent 的 detail 模式）。
- 操作统一走：点击=主操作，长按=上下文菜单，编辑模式=卡片级操作。
- 不允许：工具栏常驻、每个列表项 4 个以上元信息 chip、齿轮常驻。

## 4. 逐组件审计（当前 → 要求）

### clock

- 当前：3×2 正常模式下右上角有齿轮；时间/日期层级 OK。
- 要求：去掉正常模式齿轮（设置走长按/编辑模式）；`1×1` 只留 `HH:MM`（已符合）；秒作为 Secondary 弱化（`foreground3`）。

### todo

- 当前问题（重点）：
  1. 3×3 顶部一排 9 个控件（清单下拉、5 个视图 tab、搜索、排序、设置）；
  2. 每个任务行最多 6 个元信息（清单、时间、优先级、重复、标签、子任务进度），信息爆炸；
  3. 齿轮常驻。
- 要求：
  - 视图收敛：常驻只留 `今日 / 最近` 两个切换 + 一个 `⋯` 菜单（清单/日历/周月/热力图都进菜单）；搜索做成图标（展开后变输入框）；排序进菜单。
  - 任务行默认：勾选框 + 标题 + **最多 1 个**主元信息（逾期/今日时间/优先级点）；其余元信息在长按菜单/详情里看。
  - 设置齿轮只在编辑模式或 `⋯` 菜单里。
  - `3×2` 不显示工具条（只有清单名 + 列表 + 输入）；`2×2` 只有列表；`1×1` 计数+首条（已符合）。

### weather

- 当前（v0.3.0）：3×2 为三带式——上带当前簇（城市 / 图标 / 温度 / 现象 / 高低温）+ 今日指标
  （体感 / 降水概率 / 风，整组计 1 个 Secondary 区块），下带全宽逐时 6 列；组间 16。
  AQI 环只在 4×2、7 天只在 4×2；卡片无刷新 / 更新时间 / 齿轮。
- 要求：正常模式无 chrome（刷新、更新时间、设置都进详情）；预警 Badge 只在有预警时出现；
  3×2 不显示 AQI 环、不显示 7 天；横向空洞门禁见 §2.1 第 9 条（旧 3×2 逐时行 166px
  行内空白为反例，上带两组之间也不许留大空洞、今日指标须占满剩余宽度）；3×2 内容带 ≥70%、
  分栏空带 ≤22%；1024 断点今日指标降为 2 行且仍占满剩余宽度、不裁切（见 §2.1 第 10–11 条）。

### pomodoro

- 当前：3×2 有 环形 + 任务 + 今日统计 + 白噪音滑杆 + 3 按钮 + 齿轮。
- 要求：3×2 只留 环形时间 + 当前任务（1 行，Secondary）+ 主按钮（开始/暂停）；跳过/重置进 `⋯`；白噪音、统计进详情（点击环形打开）或编辑模式设置；齿轮去掉。

### sedentary

- 当前：3×2 有 状态点 + 分钟 + 打卡 + 统计 + 齿轮。
- 要求：3×2 只留 状态点 + 连续分钟（Primary）+ 打卡（主操作）；统计进详情；齿轮去掉。

### countdown

- 当前：3×2 列表 + 添加按钮，密度基本 OK。
- 要求：正常模式每行只留 天数 + 标题（别的没有）；添加按钮保持；齿轮（如有）去掉。

### 桌面卡片 chrome（宿主）

- 当前：每张卡片常驻 26px 标题栏 + 齿轮占位。
- 要求：**正常模式无 chrome**（纯内容，圆角卡片）；编辑模式下才出现标题、删除、改尺寸、设置按钮；悬停时最多显示一个极轻的拖拽提示，不占布局高度。

### Agent 面板

- 当前：空状态 + 建议 chips；工具调用卡片平铺参数与结果。
- 要求：工具调用默认折叠成一行（图标 + 动作 + 状态），展开才看参数/结果；长会话中只保留最近的高亮，其余弱化；来源 chips 最多首屏 3 条，更多折叠。

### 设置 / 复盘 / 插件管理页

- 设置页当前偏空，可以接受（页面本来就是低频、留白多）。
- 复盘页与插件管理页：表格/卡片正常，但确保"一屏一个主任务"，次要说明文字用 `foreground3`、能收起的收起。

## 5. 验收清单（每个组件交 before/after 时必须回答）
