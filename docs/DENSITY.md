# 信息密度与层级规范

> 目标：每个组件在每种尺寸下都做到 **glanceable（一眼看懂）**，而不是把功能平铺出来。
> 这份文档是 task-9 的验收依据；每个组件改完要对照"信息预算"逐条打勾，并交 before/after 截图。

## 1. 三条硬规则

1. **每个尺寸有信息预算**（见下表），超预算必须降级到二级区域或详情/菜单。
2. **每张卡片只有一个 Primary**：一个最大值/主状态；一个 Primary Action（可选）。
3. **Chrome on demand**：设置齿轮、标题栏、删除/改尺寸等操作，**默认不显示**，只在长按进入编辑模式或悬停时出现。
4. **静态 identity 行**（Equal Except Hue v2）：每张卡内容区第一行是 24px identity 行（20px 身份色图标 + 12px 组件名 +
   可选 trailing 辅助信息）。它**不是 chrome**——没有可交互控件、不常驻操作、不占点击热区；**不计入下面的信息预算**，
   其余门禁（最小字号、主次比、空带、内容带、横向空洞）不变。

### 1.1 硬门禁（2026-10-24，四份密度规格的共同底线，不得按插件豁免）

1. **hero 同字号**：所有尺寸档、所有插件的主数字一律 `tokens.fontSizeHero900` / `lineHeightHero900`（40/52）；**禁止按档位放大或缩小**。旧的 48/68/80/96/112 与 `Display XL` 全部作废（D-07 顶部注记、D-36 §1）。卡片“显得空”不是放大 hero 的理由：HIG §4 要求大尺寸扩展**信息层级**而不是放大已有内容，§7 说内容撑不起来的尺寸档不该存在——正确做法是加字段、换档或干脆不声明该档（`_shared/sizes.js` 的 `defineSizeFields` 让「换字段」成为唯一杠杆，见 PLUGIN-CONTRACT §4.4.2）。共享层能产出 hero 的只有 `HeroText`（`Metric` 内部同一实现）。
2. **空带门禁（2026-10-24 裁决，按档位分判据）**：
   - **≥2×1 档**：任意单块空白带 ≤22% 卡高；多块卡内容带 ≥60%，weather 3×2 ≥70%（§2.1-6、§2.1-10）。按卡高算术判定，不接受“看起来还行”。
   - **1×1 档**：改用**空带均分**判据——主内容在 identity 行以下的剩余空间垂直居中，或上下留白相等（±4 逻辑 px 内），单侧不得堆积。identity 行是固定 24 表头（§1-4），不参与居中；判据只统计 identity 行以下的主内容块。

   实测口径：单块空带 = `max(首内容上边距, 相邻内容块间距, 末内容下边距) / iframe 高`；内容带 = 内容包围盒高 / iframe 高。2026-10-24 收口复测（Edge headless，iframe 152×152 / 328×152 / 328×328 / 504×328，`?mock=1` / `?demo=1` 与宿主 init 同源）：

   | 卡 / 档 | 1×1 上下留白（均分判据） | 2×1 单块空带 | 2×2 单块空带 | 3×2 单块空带 | 3×2 内容带 |
   |---|---|---:|---:|---:|---:|
   | 番茄钟 | 主内容居中（identity 下） | 21.9% | 21.3% | 15.9% | 78.7% |
   | 久坐 | 主内容居中（identity 下） | 21.9% | 11.2% | 13.5%（空态 20.7%） | 77.4% |
   | 天气 | **22 / 22** | **21.7%** | 15.2% | 10.7% | 83.8% |
   | 时钟 | **22 / 22** | **21.7%** | — | 17.1% | **78.7%** |

   > 四档原超限值（天气 1×1 43.4%、天气 2×1 22.4%、时钟 1×1 / 2×1 22.4%）已按本轮裁决落掉：
   > 1×1 改均分判据后实测 22 / 22（±0）；两个 2×1 通过 2px 组距微调到 33/152 = 21.7%；时钟 3×2 补 4px 组距后内容带 78.7%。

3. **行节奏**：行高 44（`LIST_ROW_HEIGHT`）+ 行距 4（`spacingVerticalXS`）= 48 pitch；行数按 §2.2 公式取，放不下必须在 identity 行 trailing 写“共 X · 显示 Y”，禁止静默裁切。
4. **卡内栅格**：padding 16（`spacingHorizontalL` / `spacingVerticalL`）+ gap 8（`spacingVerticalS`），由 `CardRoot` 强制；宿主 6（`spacingHorizontalSNudge`）+ 插件 16 = 内容轴 22。
5. **Agent 入口（右下保留格）**：56×56 圆形 orb，锚点 = 网格右下角 (1418, 914)、安全距 0（`AGENT_GRID_SAFETY`）→ 1440×960 下 right 22 / bottom 46、z30、右下 1 格保留格；语音窗 516×340、对话面板 516×868（3 列宽，见 `agent/ui/entryGeometry.ts`）；编辑态隐藏（`agent.css`、`AGENT-SURFACE-CONTRACT §1`）。**方向固定为右下，不是右上**：上一轮把入口放到右上的实现已回退，旧存档若把卡片留在 (7,4)，`reconcileLayout` 会重排（host-impl §2.3）。
6. **数值出处**：文档新增数值必须是 Fluent token 或由 token 推导的整数；逐个数值的 token 出处见 [TOKEN-MAP.md](TOKEN-MAP.md)。共享原语的常量是唯一出口（`ICON_SIZE` 16/20/24/32/48、`IDENTITY_ICON_SIZE` 20、`EMPTY_STATE_ICON_SIZE` 24、`EMPTY_STATE_ICON_SIZE_LARGE` 40、`CARD_IDENTITY_HEIGHT_PX` 24、`HERO_PROGRESS_THICKNESS_PX` 4、`TOUCH_TARGET` 44、`LIST_ROW_HEIGHT` 44）；宿主侧同值常量在 `src/host/design/metrics.ts`。插件调用点直接写 `20` / `24` / `32` / `44` 字面量，与写 `37px` 同罪。

### 1.2 结构性例外：3×3 空态空带 31–33%（2026-10-24 判断性复核）

**现象**：3×3 档（内容框 440 高）的空态块固定 146 高（图标槽 32/40 + 标题 22 + 按钮 44 + 组距 24），
垂直居中后单侧空带 = (440 − 146)/2 ≈ 147 → **33%**，超 §1.1-2 的 22%。待办 3×3 与倒数日 3×3 属此列
（其余档位 ≤20.4%）。

**为什么不用文字解决**：唯一能把空带压回 22% 的做法是往空态里加一行说明文字（≈22 高）或把图标放大到
80+。前者是上一轮明确删掉的「防御性书写」——空态里唯一的动作按钮已经把「能做什么」说完了；
后者会变成装饰性大图标（HIG §4：大尺寸扩展的是信息层级，不是放大已有内容）。

**本轮的处置（观感优先，不是门禁豁免）**：
1. **更大的中性图标**：3×3 档空态图标由 24 升到 40 档位（`EMPTY_STATE_ICON_SIZE_LARGE`；
   共享层按 `sizeKey === '3x3'` 自动判定，插件调用点不需要传参）。图标仍为中性色（`colorNeutralForeground3`）。
2. **垂直居中不动**：`justify-content: center`，让留白上下均分，而不是堆在一侧。
3. **身份色暗示只在 20px identity 图标**（`--wtsl-identity` + 行尾 `ChevronRight16Regular`）：
   不把色相扩散到空态图标或色块上。理由：身份色是「这是哪个组件」的线索，不是「这里空着」的装饰；
   放大到 40 的空态图标一旦上色，就成了全卡最亮的元素，把注意力从主操作上拉走（Fluent color：色相不承担语义）。
   这一条与「用更强的身份色暗示撑住观感」的建议**有意偏离**：铁律优先，观感靠图标档位与居中解决。

**登记**：本条是**结构性例外**，不修改 §1.1-2 的 22% 门禁本身；后续若要彻底合规，只能在
「3×3 不声明空态」与「空态改上对齐并接受更大静止留白」之间选一个（产品裁决，见验证报告 §8-1）。
## 2. 尺寸信息预算

| 尺寸 | 允许的 Primary | 允许的 Secondary | 允许的 Tertiary | 主操作 |
|---|---|---|---|---|
| `1×1` | 1 个数值/状态 | 1 个标签（≤6 字） | 0 | 0 |
| `2×1` | 1 个数值/状态 | 1–2 个辅助值 | 0 | 0（点击即主操作）；**计时器类例外见下** |
| `1×2` | 1 个数值/状态 | 2–3 行列表/辅助 | 0 | 0 |
| `2×2` | 1 个数值/状态 | 2–4 项 | 0 | ≤1 |
| `3×2` | 1 个数值/状态 | 4–6 项 | 0 | ≤1 |
| `3×3` | 1 个主区域 | 列表/图表 | 1 个入口（菜单/详情） | ≤1 |
| `4×2` | 1 个主区域 | 分栏辅助 | 1 个入口 | ≤1 |

> **计时器类 2×1 主操作例外（2026-10-24）**：pomodoro / sedentary 的 `2×1` 允许 **1 个主操作按钮**
> （开始/暂停、我站起来了/我坐下了）。理由：2×1 内容宽 296 足够容纳 hero 99 + 44 按钮组 96 + 8 组距；
> 取消按钮会让该档退化成只读条（横向空洞的配套例外见 §2.1 第 12 条）。`1×2` 仍为 0 个主操作（宽度 120 放不下 hero + 控件）。
>
> **内容列表例外**：组件声明的内容列表（todo 任务行、countdown 事件行、weather 逐时/7 天、日历格）按「行/列」计为 1 个 Secondary 区块，不逐项累加；行数上限按 §2.2 公式与 D-04：todo `2×2=5`、`3×2=5`、`3×3=8`、`4×2=5`（旧 4/6/10 与 44 行高 + 空带算术冲突，已作废）；countdown `1×2=3`、`2×2=4`、`3×2=4`、`3×3=8`；weather 2×2 逐时 **4 列**、3×2 逐时 **6 列**（逐时是列，不套 todo 行数）。weather 3×2 的「今日指标」（体感 / 降水概率 / 风）整组按 **1 个 Secondary 区块**计（不按 3 项累加）。

### 2.1 量化门禁（v2，2026-10-19，来自第二版独立审计）

> 判定的物理前提：2880×1920 物理屏 = 1440×960 CSS @200% = 267 PPI，**1 CSS px = 0.1902 mm**；
> 距离 D(mm) 处 1 CSS px ≈ `653.9 / D` 弧分；20/20 视力下"舒适可读"取 ≥10′ 帽高（≈0.7em）。
> 主信息按 **1.0–1.5m 远看**，次要按 0.5–0.8m，次次要/标签 ≤0.5m。

| 角色 | 绝对下限 | 推荐 | 说明 |
|---|---|---|---|
| 主信息（数字/时间/状态） | **32px** | **40px（统一 hero）** | 32px 在 1.5m 帽高 9.8′≈2× 极限；40px=12.2′ |
| 单值卡 hero（所有尺寸档） | **40px** | **40px（唯一上限）** | Equal Except Hue v2：统一 `tokens.fontSizeHero900` / `lineHeightHero900`（40/52），不再按档放大 |
| 次要值（温度、日期、统计值、任务标题） | **14px** | 16–20px | 14px 在 0.6m 帽高 10.7′ |
| 标签（单位、星期、计数标签） | **12px** | 14px | 12px 只在 0.5m 可读 |
| 元信息（时间、逾期、行尾辅助） | **12px** | 12–14px | **10px 禁止**（任何距离都 <10′） |

**可测指标（每插件 × 每尺寸都要满足）**

1. **主信息字号**：所有尺寸档统一 `tokens.fontSizeHero900`（40 / 行高 52），不再按档放大或缩小；
   因此旧口径「主信息字号 / iframe 高度 ≥30% / ≥15% / ≥17%」作废——占比现在只由卡高决定（1×1 152 高 → 26%，2 行档 328 高 → 12%），
   对同类卡一律相同，不再是区分指标。数值卡仍必须**只有一个** hero 数字。
2. **主次字号比** ≥2.0（数值卡）或 ≥1.5（列表头 vs 组头/行标题）。
   > **列表卡口径（2026-10-24，countdown 归入纯列表卡）**：countdown 与 todo 都按纯列表卡处理——
   > 头部只放 12px fg3 分组/计数标签，行标题 16 承担主信息；countdown 的剩余天数 hero **只出现在
   > featured 单条主事件块**，不再把事件总数做成 40px 列表头。两者都不套用「列表头主层 ≥28」，
   > 行标题/元信息比按 16/12 记；`verify-widgets` 用行预算、行高 ≥44、行标题 16px、头部文案存在
   > 等结构断言。
3. **最小字号** ≥12px；`<12px` 文本数必须为 0。
4. **尺寸递增**：同一插件相邻尺寸档的独立信息项数必须 +1 或更多；持平视为"只缩放不重排"，不合格。
5. **3×2 不得更空**：同插件 3×2 的内容覆盖率（文本+图标包围盒并集高度 / 卡高）必须 > 1×1。
6. **空带**：≥2×1 档任意单块空白带 ≤22% 卡高；1×1 档按上下留白均分判据（§1.1-2）；多块卡片内容带 ≥60% 卡高。
7. **行预算**：列表行高 ≥44px（= `TOUCH_TARGET` 44）、行间距 4；行数 = `min(cap, floor((A + 4) / 48))`，
   `A = Hc − 24 − 8 − (Hf ? 52 + 8 : 0)`（`Hc` 为 iframe 内容框高，已扣卡片 16×2；`Hf` 为 featured hero 行高 52）。
   放不下的必须在 identity 行 trailing 写“共 X · 显示 Y”，禁止静默裁切；各档 cap 与实测 slack 见 §2.2。
8. **字号只走字阶**：Fluent `Text size` 或 `fontSizeBase*`/`fontSizeHero*`（Base100–600 + Hero700–1000）；
   数字型主信息统一 `fontSizeHero900` / `lineHeightHero900`（40/52），**不定义项目级字号变量**（D-07 的 `Display XL` 48/80/96/112 已作废）；禁止 `lineHeight: 1`。
9. **横向空洞（v0.3.0，2026-10-20）**：卡片内同一视觉行里，相邻内容单元（flex row 子项 / grid 行内列单元，**不含无内容的布局占位**）之间的连续水平空白 ≤ **40px**。
   - **分栏口径**：同一条带（`data-content-band`）内横向并排的直接子分栏之间，连续水平空白 ≤ **40px**；不得用 `space-between` 把两组推到两端而留出大块中间空洞（grid gap / 组间距本身也须 ≤40）。
   - **定义列表例外**：label 左 / value 右对齐的定义列表行（如 weather 3×2 今日指标）按值列对齐处理，行内留白不算空洞；但该结构必须整块占满剩余宽度、右缘与卡片内容右缘对齐。
   - `scripts/verify-widgets.mjs` 同时测两种口径：内容单元相邻间距（`horizontalMaxGap`）与条带内分栏间距（`bandHorizontalMaxGap`），weather 3×2 均断言 ≤40px。旧 3×2 逐时行里 flex spacer 造成的 166px 行内空白即反例。
10. **3×2 内容带（v0.3.0，weather 三带式）**：整卡内容带 ≥ **70%** 卡高（高于通用 60%）；同时「分栏口径」：
    任一内容分区（`data-content-band` 的直接子分栏）在其 band 内的最大连续垂直空白 ≤ **22%** 卡高（含 lead/trail/internal）。
11. **Secondary 区块结构（v0.3.0，weather）**：3×2 的 Secondary 区块数必须比 2×2 多 1
    （`data-secondary-block` 计数；3×2 = 今日指标组 + 逐时 2 个，2×2 = 逐时 1 个），保证「尺寸变大 → 信息量变多」有可测结构依据。
12. **计时器类 2×1 横向空洞例外（2026-10-24）**：`pomodoro` / `sedentary` 的 **2×1** 允许「hero 左 / 主操作右」两端分布，
    两个内容单元之间的连续水平空白**可以超过第 9 条的 40px 上限**（296 内容宽下 hero ≈99 + 按钮组 96，实测中间约 69px）。
    理由：2×1 的整卡主操作是「打开详情」，而「开始/暂停」「我站起来了/我坐下了」是就地控件；
    只有把主操作贴到尾缘，才符合 HIG §6「主次用样式、不用尺寸」与「每个视图 1–2 个突出按钮」——
    把按钮拉到 hero 旁边会让两个元素互相削弱，也破坏「控件在行尾」的稳定位置。
    - **该例外只对计时器类的 `2×1` 生效**。`1×1`（120 宽放不下 hero 40 + 按钮组 96）、`2×2` / `3×2` / `3×3` 仍按第 9 条判定；
      列表卡（todo / countdown）、数据卡（weather / clock）一律不适用。
    - 例外只覆盖横向空洞，其他门禁不变：单块空带 ≤22%、内容带 ≥60%、3×2 ≥70%、分栏空带 ≤22% 照旧。
    - `scripts/verify-widgets.mjs` 的 `horizontalMaxGap` / `bandHorizontalMaxGap` 需要按本例外放行
      （建议按「插件 id + 尺寸档」白名单，或识别计时器卡片根上的 `data-timer-split="true"`）；
      脚本不在本轮写入范围，登记给下一批。

13. **进度带厚度 4px（2026-10-24）**：卡片内进度带一律厚 `tokens.strokeWidthThickest`（Web 档 **4px**），
    经共享 `HERO_PROGRESS_THICKNESS_PX` 暴露；**不得写 `tokens.strokeWidthThicker`**——Fluent `shapes.md` 的
    stroke 表里 Web 档 Thicker 是 **3px**（4px 是 Mobile 档，见 `references/fluentui-design/shapes.md:67-72`），
    用它会得到 3px 带，与 4px 规格冲突。颜色固定 `colorBrandBackground`、轨道 `colorNeutralBackground3`；
    `active=false`（未运行）时保留 4px 占位并 `visibility:hidden`，**不重排**、不出画。插件不自绘进度带
    （PLUGIN-CONTRACT §4.4 `HeroProgress`）。

### 2.2 D-04 行预算：按公式重算（2026-10-24）

几何前提：2×2 / 3×2 的 iframe 内容框高 `Hc = 296`（328 − 16×2），3×3 `Hc = 472`；
行高 44 + 行距 4 = 48 pitch；`A = Hc − 24 − 8 − (Hf ? 52 + 8 : 0)`；`N = min(cap, floor((A + 4) / 48))`。

| 卡 | 档 | Hc | A | 公式 N | cap（D-04） | 实际行数 | slack | 最大空带 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| todo | 2×2 | 296 | 264 | 5 | **5**（旧 4 作废） | 5 | 28 | 8.5% |
| todo | 3×2 | 296 | 264 | 5 | 5 | 5 | 28 | 8.5% |
| todo | 3×3 | 472 | 440 | 9 | 8 | 8 | 60 | 11.6% |
| todo | 4×2 | 296 | 264 | 5 | 5 | 5 | 28 | 8.5% |
| countdown | 1×2 | 296 | 204 | 4 | 3 | 3 | 64 | 18.8% |
| countdown | 2×2 | 296 | 204 | 4 | 4 | 4 | 16 | 4.7% |
| countdown | 3×2 | 296 | 204 | 4 | 4 | 4 | 16 | 4.7% |
| countdown | 3×3 | 472 | 380 | 8 | 8 | 8 | 0 | 0% |

- **2×2 的 cap 从 4 改 5 是算术结论**：`A=264`，cap 4 时 4 行占 188、slack 76 = 328 卡高的 **23.2% > 22%**；
  cap 5 时 5 行占 236、slack 28 = **8.5%**。旧口径「328 − 24 − composer 40 − 组间距 16 = 248」基于已删除的
  工具条/composer，作废（`DECISIONS.md D-04` 已同步修订）。
- **countdown / todo 都不套“列表头主层 ≥28”**：countdown 是纯列表卡（§2.1-2），todo 的 1×1 计数是唯一 hero；
  其余行标题 16、元信息 12，行预算按上表。
- **weather 例外**：逐时是“列”不是“行”，2×2 = 4 列、3×2 = 6 列（列宽 ≥72），不套用本表行数。

**间距（全部 spacing token，按尺寸档固定映射）**

| 尺寸 | 卡片 padding | 组间距 | 列表行间距 |
|---|---|---|---|
| 所有尺寸档 | **16** | **8** | **4** |

> 列表行间距是 4（`spacingVerticalXS`），与行高 44 组成 48 pitch；旧表的 8 与行预算公式冲突，已改。

- Equal Except Hue v2（2026-10-24）：唯一卡片内容栅格，4px 基线 → 8px 步长；旧的分尺寸 padding 表作废。
- 不允许用 0 或 2px 作为内容行距；插件不得各自覆盖 padding/gap，统一由共享 `CardRoot` 提供。
- 图标与文字统一 8；20px identity 图标 + 12px 标签。

**层级表达手段（只用 Fluent token）**

- 字号：Primary 用 Fluent `Text size` / `Hero*`；所有主数字统一 `fontSizeHero900` / `lineHeightHero900`（40/52），**D-07 的 `Display XL` 48/80/96/112 已作废**。Secondary 用 `Base300/400`，Tertiary/微标签用 `Base200`；严格遵守 §2.1 的最小字号与主次比，不靠加粗堆层级。
- 颜色：Primary `colorNeutralForeground1`，Secondary `colorNeutralForeground2`，Tertiary `colorNeutralForeground3`；组件 identity 色只出现在 20px identity 图标（`--wtsl-identity`），不参与层级、不用于背景/按钮/空态。
- 分组：用 `spacingVertical*` 留白分组，**不靠边框/分割线**（Fluent 2 的 card 内部默认无分割线）。
- 操作：次要操作收进 `Menu`，图标按钮必须有 `Tooltip`。

## 3. 渐进披露

- 卡片默认只显示 Primary + 必要 Secondary。
- 详情统一进 `OverlayDrawer`/`Dialog`（Fluent 的 detail 模式）。
- 操作统一走：点击=主操作，长按=上下文菜单，编辑模式=卡片级操作。
- 不允许：工具栏常驻、每个列表项 4 个以上元信息 chip、齿轮常驻。

### Agent 面板

- 当前（v0.4.3）：一轮回答 = 一个**轮次卡**（思考 → 工具步骤 → 正文，一个折叠控制）；空状态 + 建议 chips。
- 要求：
  1. **工具调用默认折叠成一行**：折叠态 = `N 个步骤` + 一步摘要（有失败先说失败那一步）+ 行尾固定 `● N 失败`
     （danger 色，不被摘要截断）；展开才看参数/结果/错误；失败内联在该轮，不单独成块。
  2. **一条回答只有一个折叠控制**（HIG §7:113）：思考与工具合并进同一个折叠头，不再有独立工具卡与「还有 N 个工具…」出口。
  3. **一屏一个进行中指示器**（FLUENT2 §12）：半高/全高都只有一行状态（`正在思考…` / `正在调用工具：<名>` / `正在生成…` + 已用秒数），不再在列表尾部另放第二个 spinner。
  4. **失败轮不留空气泡**：本轮没有任何正文/思考/步骤时，不渲染气泡壳；错误提示条（`MessageBar` + 重试）内联在本轮，同一条错误只渲染一次。
  5. **停止有回声**：半高窗停止后状态行改述为「已停止」（warning 色 + 图标，`role=status`），停留 3 秒后淡出。
  6. **半高 peek 最多 2 条**（340 高容量：2 × 68 + 间距 8 = 144 ≤ 192，3 条 220 放不下）；流式中的最后一条看尾部（跟读），历史条目看头部；
     **块级标记先剥再渲染**（`##`、`-`、`>`、`1.`、分割线、表格行不上屏），行内元素照常，裁切不出现半个语法符号。
  7. **全高正文支持块级 Markdown**：标题 / 列表 / 围栏代码块（等宽块，长行在块内横滚）/ 表格（表头 + 数据行，窄容器横滚）。
  8. **来源 chips 最多首屏 3 条**，更多折叠。
- 未实现（保留要求，需单独立项）：长会话中只保留最近的高亮、其余弱化（全仓仍无对应逻辑）。
