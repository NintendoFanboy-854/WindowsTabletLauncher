## 0. 结论速览

**P0 = 1 项，P1 = 9 项，P2 = 11 项，P3 = 1 项。** 问题不是在"某个字号小了一点"，而是三层结构性缺陷：

1. **天气插件的 Primary（当前温度）根本没有渲染出字号**：代码用了 Fluent v9 不存在的 token 名（`fontSizeBase700/800/900`，正确名是 `fontSizeHero700/800/900`），5 处 `font-size` 声明被 CSS-in-JS 静默丢弃，温度继承到 **14px** —— 比它下面的 7 天预报最高温（16px）还小。这是全项目唯一的 P0，但它在天气的全部 5 个尺寸里都出现（R-01 / H-01）。
2. **大尺寸没有承担更多信息，反而更空**：非列表插件的 3×2 内容覆盖率只有 **12.5%–17.8%**，低于它们自己的 1×1（24.7%–28.3%）；clock/pomodoro/sedentary 的 3×2 内容带只占卡高 **22%–40%**。四种尺寸的"信息量变了"这条硬要求，在 clock 2×1→3×2、pomodoro 2×2→3×2、sedentary 2×2→3×2 上都不成立（D-01/D-02/D-03/D-05）。
3. **10–12px 微字号被用来"填满"，而不是用层级组织信息**：weather 逐时标签 **10px**、AQI 标签 **10px**、7 天标签 12px；todo 行元信息 **10px**（时间/已逾期）在 2×2/3×2/3×3/4×2 全部出现。12px 在 0.5m 处帽高只有 11.0′，10px 只有 9.2′，低于"近看可读"的 10′ 下限（R-02/R-03）。

**每个插件一句话诊断**

|---|---|
| clock | 主时间在 1×1/2×1 只有 40px（占卡高 26.3%），3×2 只有 68px（20.7%）且 60% 面积空白——"墙钟"没有成为视觉锚点（R-04/D-05） |
| countdown | 1×1 在"今天"事件时只剩两行 12px、没有主信息；2×2/3×2 最大字号只有 16/20px，3×2 标题与数据同为 20px 相互竞争 |

**最严重的 5 条**

1. **R-01（P0）** weather 温度字号 token 名错误 → 全尺寸 14px。证据：`Card.jsx:84/89/111/133/160`、Fluent token 类型定义 `node_modules/@fluentui/tokens/dist/index.d.ts:326-337`、实测 `weather-1x1-1440x960.json`（`24°` = 14px）。

3. **D-01（P1）** "3×2 比 1×1 更空"：clock/pomodoro/sedentary 3×2 覆盖率 12.5%–13.2% vs 各自 1×1 的 24.7%–27.0%。`summary-standalone.md`。
4. **D-02（P1）** sedentary 2×2→3×2 信息项 9→9 完全不变，只把数字 28→32px、padding 8→16px；`SedentaryApp.jsx:214-223, 295-355`。
5. **R-04（P1）** clock 主时间占比 26.3%（1×1）/26.3%（2×1）/20.7%（3×2），用户"现在的时间字号还是太小"的判断成立；宿主默认桌面 `desktop-1440x960.png` 里时钟是 2×1 → 40px。

## 2. 判定标准（先定标准，再判对错）

### S0 物理口径与换算

- 目标屏由项目文档确定：`docs/RELEASE.md:16` "窗口全屏 2880×1920（1440×960 epx @200%）"；13″ 3:2 2880×1920 面板 = **267 PPI**。因此 **1 CSS px = 2 物理 px = 0.1902 mm**。
- 视角换算：`1 CSS px 在距离 D(mm) 处 = 653.9 / D 弧分`（近似，D≫px）。正文数字按 20/20 视力、字母高 ≈ 0.7em 计算帽高（cap）。
- 视距分档：**主信息目标 1.0–1.5 m（远看）**；**次要 0.5–0.8 m（近看）**；次次要 ≤0.5 m（凑近看）。

**判据锚点（帽高弧分，20/20 视力：1′ 分辨极限、5′ 字母可辨、10′ = 2× 余量"舒适可读"）**

| 字号 | 0.5 m | 1.0 m | 1.5 m | 2.0 m | 可承担角色 |
|---|---|---|---|---|---|
| 10px | 9.2′ | 4.6′ | 3.1′ | 2.3′ | **不合格**（0.5m 也低于 10′） |
| 12px | 11.0′ | 5.5′ | 3.7′ | 2.7′ | 仅 0.5m 标签 |
| 14px | 12.8′ | 6.4′ | 4.3′ | 3.2′ | 0.6m 次要值 |
| 16px | 14.7′ | 7.3′ | 4.9′ | 3.7′ | 0.8m 次要值 |
| 20px | 18.3′ | 9.2′ | 6.1′ | 4.6′ | 1.0m 次要/标题 |
| 24px | 22.0′ | 11.0′ | 7.3′ | 5.5′ | 1.2m 标题 |
| 28px | 25.6′ | 12.8′ | 8.5′ | 6.4′ | 1.2m 主信息下限 |
| 32px | 29.3′ | 14.7′ | 9.8′ | 7.3′ | **1.5m 主信息下限** |
| 40px | 36.6′ | 18.3′ | 12.2′ | 9.2′ | 1.5m 主信息达标 |
| 48px | 44.0′ | 22.0′ | 14.7′ | 11.0′ | 2m 主信息可用 |
| 68px | 62.3′ | 31.1′ | 20.8′ | 15.6′ | 2m 主信息达标 |
| 96px | 87.9′ | 44.0′ | 29.3′ | 22.0′ | 大卡主信息 |

> 换算复核：40px 在 1.5m = 40×653.9/1500/… em 弧分 = 17.4′，帽高 12.2′，恰为 2.4× Snellen。这与"1–1.5m 一眼可读"一致；32px 帽高 9.8′≈2× 极限；14px 在 0.6m 帽高 10.7′，是"近看可读"的合理下限。

### S1 绝对字号阈值（本项目 · 暗色平板 · 0.5–2m）

| 角色 | 下限 | 推荐 | 依据 |
|---|---|---|---|
| 主信息（数字/时间/状态） | **32px** | 40–96px（按尺寸档） | 32px=1.5m 帽高 9.8′；40px=12.2′ |
| 单值卡（1×1 / 2×1 的 hero） | 40px | **48–68px** | 屏上只有一件事，必须一眼即读 |
| 次要值（温度、日期、统计值、任务标题） | **14px** | 16–20px | 14px 在 0.6m 帽高 10.7′ |
| 次次要/标签（单位、星期、计数标签） | **12px** | 14px | 12px 在 0.5m 帽高 11.0′ |
| 元信息（时间、逾期、列表辅助） | **12px** | 12–14px | 10px 在任何距离都 <10′，**禁用** |

### S2 主信息占比（可测量，防"整体偏小"）

- `主信息字号 ÷ 卡片内容区高度`（下文"卡高"均指 iframe 视口高度，即宿主卡片外框 −12px）：

| 尺寸 | 占比下限 | 绝对下限 | 说明 |
|---|---|---|---|
| 1×1 | **30%** | 40px | 152px 卡 → ≥46px（受宽度约束，HH:MM 类不超过约 48px） |
| 2×1 | **30%** | 40px | hero 建议 68px（44.7%） |
| 2×2 | 12.5%（数值卡）/ 列表头 28px | 40px | 328px 卡 → ≥41px |
| 3×2 | **15%**（数值卡）/ 列表 hero 32px | 48px | 328px 卡 → ≥49px |
| 3×3 | 列表头 28px、行标题 16px | — | 列表型卡片用"列表头主层"代替单值 |
| 4×2 | **17%**（数值卡）/ 列表头 28px | 56px | 328px 卡 → ≥56px |

- 宽度约束（同等重要）：主信息单行宽度 ≤ 内容区宽度的 90%；这决定了 1×1 时钟"HH:MM"最大约 46–48px（实测 40px 时占宽 102/136=75%，比例 2.55 em/字串宽）。

### S3 信息预算与"信息量必须变"

- 信息预算沿用 `DENSITY.md:14-24`（1×1：1 主+1 标签；2×1：1 主+1–2 次；2×2：1 主+2–4 项；3×2：1 主+4–6 项；3×3/4×2：1 主区+列表/分栏+≤1 入口），并补两条可测量规则：
  - **S3a 严格增量**：同一插件相邻尺寸档（按支持顺序）的"独立信息项数"必须增加 ≥1；持平即"缩放而非重排"，记 D 类。
  - **S3b 行预算**：列表行数按 `DENSITY.md:24` + 实测可用高度；放不下的行必须有滚动提示或降低行数预算，不允许静默裁切（todo 3×3@1024 违反）。

### S4 空白 / 拥挤（多块卡片）

- **空带**：除单值卡（1×1/2×1）外，卡片任一连续无内容带 ≤ **22% 卡高**；1×1/2×1 允许对称留白，但主信息占比必须过 S2。
- **内容带**：≥2×2 的多块卡片，首内容→末内容的高度 ≥ **60% 卡高**。
- **覆盖率**（文字+图形包围盒并集，4px 网格）：多块卡片目标 **25%–60%**；低于 20% 视作"过空"，高于 65% 视作"过密"。
- **对称性**：上下空带差 >15% 卡高时，视作布局失衡（内容悬空）。
- **拥挤**：同一卡片内 ≥30 个文本节点或一行出现 ≥3 个同级元信息 → 过密。

### S5 层级

- 只有**一个 Primary**：全卡字号最大的"信息组"唯一；同一尺寸档内不允许两个互不相关的元素使用同一最大字号（如标题与数据同 20px）。
- 层级数：1×1/2×1 ≥2 档；2×2/3×2/3×3/4×2 ≥3 档（主/次/次次）。
- 相邻层级字号比 ≥1.5（数值卡主:次 ≥2.0）；层级同时用颜色（Foreground1/2/3）与间距表达，不靠加粗。

### S6 小字号硬规则

- 任何可见文本 **<12px 即违规**；**10px 禁用**（当前 weather 单场景最多 6 处、todo 单场景 3–6 处）。
- 12px 只能用于标签（单位、星期、计数说明），不得用于值/任务标题/元信息。
- 对比度：已实测全部启用文本 ≥4.5:1（禁用态 todo 已完成行 2.46:1，WCAG 豁免；见 P3-01）。

### 5.4 小字号被当作"填满"手段

- weather 2×2/4×2：6 处/1 处 10px；todo：10px 元信息在 4 个尺寸里都有（每个场景 3–6 处）；另有 12px 值/标题 30+ 处。
- 这些字号的共性是"放在卡片边缘/底部"（逐时行、行尾时间、AQI 标签）——正是"DENSITY 规则 1：超预算必须降级到二级区域或详情，而不是缩字号塞进卡片"的典型反例。
- 修复方向不是"整体放大字号"（会溢出），而是**删掉超预算项**（weather 2×1 删城市、todo 元信息只留 1 项）**并把留下的项升到 ≥12/14px**。

### 5.5 宿主层

1. **960×1440 竖屏默认布局**：9 行网格只用 3 行（顶部），下方 55% 空白（`host/desktop-960x1440.png`）。这是默认布局策略问题（6 个默认组件没有按行数扩容），不是插件视觉缺陷；建议竖屏默认给组件更大的默认尺寸（如 clock 2×1→3×2、weather 3×2→4×2 或换页）。
2. **1024×768 默认布局**：pomodoro 被挤到第二屏下右、远离其他卡片（`host/desktop-1024x768.png`），桌面的"扫一眼"路径从 3 行变成 L 形；属布局算法（autoPlace/cleanup）的观感问题，P3。
3. **desktop dock 常驻右下**（Agent/复盘/插件/设置）：与"桌面即内容"有张力，但属产品决策（旧审计已记录），本轮不重复计。
4. **宿主 dev 构建的布局持久化缺陷（功能，非视觉）**：写入 `wtsl.layout` 后 reload 会被默认布局覆盖（实测 `debug6`：clock 自定义坐标 6,0 在 reload 后回到 0,0）。这也是本轮无法用宿主做逐尺寸截图的原因；建议单独修（超出本次 UI 视觉审计范围，记作方法学限制）。

### 6.4 验收断言（可机器检查）

对每个插件每个尺寸，用 CDP/DOM 测量断言：

1. `maxFontSize ≥ S2 下限`（1×1≥40、2×1≥40、2×2 数值≥40、3×2 数值≥48、4×2 数值≥56；列表卡 header≥28）。
2. `maxFontSize / cardHeight ≥ S2 占比`（1×1/2×1≥30%、2×2≥12.5%、3×2≥15%、4×2≥17%）。
3. `maxFontSize / secondTierFontSize ≥ 2.0`（数值卡）或 `≥1.5`（列表头）。
4. `minFontSize ≥ 12`，且 `<12px` 文本数 = 0。
5. 多块卡片 `maxEmptyBand ≤ 0.22 × cardHeight`、`contentBand ≥ 0.60 × cardHeight`。
6. 同一插件相邻尺寸 `infoItemCount(n+1) ≥ infoItemCount(n)+1`。
7. `3×2` 覆盖率 > 同插件 `1×1` 覆盖率。
8. 列表卡行数 = min(rowBudget, floor(可用高度/最小行高 44))，且无静默裁切。
