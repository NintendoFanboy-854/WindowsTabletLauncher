# 技术选型

启动器使用 **WinUI 3 + Windows App SDK + .NET** 构建。WinUI 3 是微软推荐的现代 Windows 桌面应用原生 UI 框架，实现了 Fluent Design System，提供 Mica/Acrylic 材质、ConnectedAnimation 动画系统、原生触控手势和 Windows 摄像头/麦克风 API 的一等集成。

插件 Widget 以 WinUI `UserControl` 作为内容容器，Host 基于 WinUI `Window` 绘制全屏桌面层。

# 设计分层

这个启动器的 API 设计借鉴操作系统的内核层与用户层分层思路。

内核层就是启动器 Host。它负责整个桌面的运行环境，包括窗口、动画、输入、插件生命周期、Agent、人脸识别、语音监听和全局状态管理。

插件是普通的 C# 程序集，和 Host 运行在同一个进程里。它们可以直接调用 Windows API 或 .NET 库访问系统资源，不需要 Host 作为唯一中介。Host 提供的是共享的便利服务，例如统一的配置存储、通知发送、页面管理和动画系统。插件可以选择使用这些服务，也可以自己处理。

用户层就是插件。插件只负责提供内容和行为逻辑。它不需要关心窗口怎么管理、动画怎么播放、页面怎么切换。它只需要告诉 Host 自己占多大地方、背景要什么材质、内容长什么样、Agent 能不能调用自己。

# 内核层（Host）

## 窗口与 Shell 管理

Host 负责创建和维护一个全屏窗口。这个窗口没有标题栏、没有边框、没有系统按钮。它覆盖整个屏幕，作为所有 Widget 的容器。

Host 管理多个页面。每个页面上有一组按网格排列的 Widget。用户可以通过左右滑动切换页面，也可以通过 Host 提供的设置调整页面数量。

Host 负责在不同状态之间切换，例如正常浏览模式、编辑模式、覆盖层模式。状态切换时的过渡动画也由 Host 处理。

## 动画系统

所有动画归 Host 所有。插件不编写动画，也不触发动画。插件只提供静态或动态变化的内容，Host 负责让内容的显隐、移动、缩放、切换变得平滑。

Host 提供的动画包括：

- Widget 插入和删除时的缩放淡入淡出。
- 用户左右翻页时的页面滑动或交叉淡入淡出。
- 长按进入编辑模式时的过渡效果。
- Widget 被拖拽时的位置微动效。
- 覆盖层出现和消失时的组合动画。
- 焦点在 Widget 之间移动时的反馈动画。

Host 使用 WinUI 3 的 ConnectedAnimation 和 Composition API 来实现动画。对于页面切换可以使用 EntranceThemeTransition 或自定义 Composition 关键帧动画，配合 WinUI 内置缓动函数（如 CubicEaseOut、BackEase、PowerEase 等）。Widget 的显隐可以使用 EntranceThemeTransition / FadeOutThemeTransition 等内置过渡动画。

## 输入路由

Host 统一接收所有输入事件，包括触控、鼠标、键盘和触控板。

Host 先识别全局手势，例如：

- 左右滑动切换页面。
- 长按进入编辑模式。
- 捏合手势进入或退出编辑模式。
- 全局快捷键显示或隐藏启动器。

如果输入事件落在某个 Widget 区域内，Host 将事件转发给该 Widget 对应的 WinUI UserControl。插件在自己的 UserControl 内处理点击、拖拽、滚轮等具体交互。

## 插件生命周期管理

Host 在启动时扫描插件目录，动态加载每个插件 DLL，并调用其初始化方法。Host 给每个插件传递一个 Host 句柄，插件通过该句柄访问内核层服务。

插件初始化完成后，向 Host 返回它提供的 Widget 列表和可选的后台服务列表。Host 根据 Widget 声明的尺寸和位置偏好，把它们摆放到合适的页面和网格位置上。

当用户禁用某个插件或退出启动器时，Host 调用插件的关闭方法，释放资源。

## Agent 与人机交互

Agent 是 Host 的核心组件之一，不是插件。它包含自然语言理解、语音识别、语音合成、人脸识别和头部姿态识别等能力。

Host 持续通过摄像头检测人脸。当识别到已注册的人脸时，自动启动语音监听模式，用户可以直接用语音与 Agent 交互。Agent 也支持识别简单的头部动作，例如点头和摇头，作为语音之外的辅助确认方式。

语音对话本身通过云端大语言模型 API 实现，不运行在本地。本地只负责录音、唤醒、播放语音和转发请求。

插件可以主动向 Agent 注册自己的能力，包括：

- 可以回答什么问题。
- 可以执行什么动作。
- 每个动作需要什么参数。

Agent 通过 Host 内部的插件注册表调用插件。插件返回结果后，Agent 可以选择直接语音回复用户，或者再调用其他插件组合出最终答案。

Agent 可以联网，也可以访问插件声明之外的数据。权限和隐私由用户自行控制，不作为 Host 的核心设计约束。

## 配置与状态持久化

Host 提供一个统一的配置存储接口给插件使用。每个插件有自己的配置命名空间，互不干扰。插件可以读取自己的设置，也可以保存自己的状态。

Host 本身也持久化全局设置，例如页面布局、Widget 位置、主题变体、语言设置等。

## 通知服务

插件可以通过 Host 发送通知。通知可以是系统级气泡通知，也可以是 Host 内部的通知条。具体形式由 Host 决定，插件只提供标题、内容和优先级。

# 用户层（Plugin）

## 插件入口

每个插件实现一个入口接口。Host 通过该接口与插件交互。

入口接口包含以下方法：

- 初始化：接收 Host 句柄，完成插件自身的设置。
- 返回 Widget 列表：告诉 Host 这个插件提供哪些 Widget。
- 返回后台服务列表（可选）：告诉 Host 这个插件有哪些在后台运行的能力。
- 关闭：释放资源，保存状态。

## Widget

Widget 是插件提供的可视化单元。每个 Widget 向 Host 声明以下信息：

- 唯一标识。
- 显示名称。
- 支持的尺寸列表，例如 1x1、2x1、2x2、4x2 等网格单位。
- 当前选中的尺寸。
- 背景模式：None 或 Acrylic。
- 创建一个 WinUI UserControl 的方法，Widget 的内容就在这个 UserControl 里绘制。
- 可选的 Agent 交互入口，用于回答查询或执行动作。

Widget 只负责内容显示。它不管理自己的位置、动画、生命周期和事件路由。这些内容全部由 Host 处理。

## 后台服务

插件可以不提供任何 Widget，只提供后台服务。后台服务在插件初始化后持续运行，不占据桌面空间。

后台服务通常用于：

- 定时任务，例如久坐提醒的计时器。
- 系统状态监控，例如电池、网络、音量变化。
- 其他不需要显示在桌面上的周期性工作。

后台服务可以通过 Host 的通知服务或 Agent 接口与用户交互。

## 覆盖层请求

某些插件需要在特殊情况下占据整个屏幕，例如久坐提醒的强提醒模式。插件不应该自己创建全屏窗口，而应该请求 Host 显示一个覆盖层。

插件在请求覆盖层时提供：

- 覆盖层中间要显示的内容，通常是一个 WinUI UserControl。
- 请求的级别，例如普通提示、强制提醒、需要用户确认才能关闭。

Host 负责：

- 把背景 Widget 层模糊或变暗。
- 把遮罩和提醒内容以动画方式呈现。
- 处理用户关闭覆盖层的方式，例如点击按钮、按 Esc、等待超时。

这样插件只关心提醒内容本身，动画和层级都由 Host 控制。

# 内核层与用户层的交互边界

## Host 不介入插件内部

Host 只调用插件暴露的接口，不会读取插件的内部状态或直接操作插件的私有控件。插件自己决定内容怎么画、数据怎么存、逻辑怎么走。

## 插件可以直接访问系统资源

插件是 C# 代码，可以直接调用 Windows API 或 .NET 库来访问摄像头、麦克风、网络、文件系统等资源。Host 不会强制拦截或代理这些访问。

Host 提供一些共享的便利服务，例如统一的通知发送、配置存储、页面管理和动画系统。插件可以选择使用这些服务来减少重复代码，但这不是强制的。

摄像头和麦克风主要由 Host 的 Agent 模块用于人脸识别和语音监听。如果某个插件确实有特殊需求需要使用摄像头或麦克风，它也可以自己直接访问。

## Agent 通过 Host 调用插件

Agent 不会直接实例化插件或访问插件内部。Agent 向 Host 发出调用请求，Host 再转发给对应的插件。插件返回结果后，Host 把结果传回 Agent。

## 动画只能由 Host 产生

插件不能自己创建窗口级或页面级的动画。插件 UserControl 内部可以有小幅的局部动效，例如进度条变化、数字跳动，但 Widget 的插入、删除、移动、翻页、编辑模式切换、覆盖层等动画全部由 Host 控制。

# 总结

Host 是舞台、灯光、镜头和导演。它决定整个桌面怎么运行、怎么动、怎么响应输入。

插件是演员。它们只负责上台表演什么内容，不负责舞台怎么搭建、镜头怎么运动。

Agent 是主持人兼现场导演助理。它包含人脸识别、语音监听、头部姿态识别和自然语言理解，负责在合适的时机把用户意图传达给正确的插件。
